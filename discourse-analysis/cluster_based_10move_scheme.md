# 基于用户聚类的 10-Move 整合方案

> 用户将 19 个 Move 归为 6 个语义簇（A–F），本方案在此基础上**有理有据**地细化为 **10 个 Move + OTHER**，并说明每一处拆分/合并的理由。  
> 可执行方案与提示词见 `move_scheme_v3.md` / `llm_move_annotation_prompt_v3.md`（Move 定义与边界准则相同）。

## 二、从 6 簇到 10 Move 的拆分/合并决策

### 决策 1：簇 A 拆分为 2 个 Move（历史 vs. 声誉）

- **M02 历史沿革与共同体敬意** = M02（历史）+ M19（缅怀，低频，合并为子类型）
- **M08 学术声誉与办学成就** = M09（声誉）+ M17（dated news，若与声誉强相关）
- **理由**：Yu (2023) 以"communicative purpose"为命名准则，"证明卓越" (M09) 与 "追溯历史" (M02) 的目的不同；缅怀 (M19) 出现率 < 5%，并入 M02 降低负担，保留 `(tribute)` 子类型注记以便筛选。

### 决策 2：簇 B 拆分为 3 个 Move（价值/目标/愿景）

- **M03 价值准则、学科内涵与社会服务** = M03 + M04 + M11 + "回应公共议题"
- **M05 育人目标、教学模式与毕业出路** = M06 + M12
- **M10 未来愿景、欢迎与联系信息** = M13 + M14 + M15 + M18（低频募捐并入，保留子类型）
- **理由**：Yu (2023) 区分"当前使命"与"未来规划"；培养目标 (M06) 与毕业出路 (M12) 均属"教育全程"话语，合并为 M05 不损失 RQ2 分析（职业导向表述仍可识别）；募捐 (M18) 低频且修辞功能特殊，并入 M10 时保留 `(philanthropy)` 子类型。

### 决策 3：簇 C 保留为 2 个 Move（学科 vs. 研究）

- **M03**（已包含 M04 学科内涵）：学科必要性论证面向学科/公众
- **M06 研究议程与学术取向** = M07
- **理由**：主语不同（学科本身 vs. 本院系），RQ5 需要分别识别"多语种/跨学科资源"与"研究议程"；合并会模糊 RQ3/RQ5 的分析。

### 决策 4：簇 D 拆分为 3 个 Move（课程/研究/资源）

- **M04 学位项目与课程供给** = M05
- **M06 研究议程与学术取向** = M07（与簇 C 共享）
- **M07 师资力量与支撑资源** = M08
- **理由**：Yu (2023) 以 communicative purpose 为准则，"提供课程" (M04)、"研究什么" (M06)、"有哪些资源" (M07) 三者的修辞目的不同，合并会降低 RQ1 的 Move 频率分辨率。

### 决策 5：簇 E 拆分为 1 个 Move + OTHER 子类型

- **M10**（已包含 M14 欢迎 + M15 联系）：欢迎/行动/联系合并
- **M18 募捐** → OTHER，保留 `(philanthropy)` 子类型
- **理由**：Yu et al. (2026) 的 OTHER 标签吸收所有不匹配 Move；募捐在中美 About Us 中出现率差异大（中国 < 5%，美国部分有），作为 OTHER 子类型可保留统计可追溯性，同时降低主 Move 数。

### 决策 6：簇 F 拆分为 1 个 Move + OTHER

- **M10**（已包含 M15 联系）：联系信息合并入 M10
- **M16 规章** + **M17 动态** → OTHER，保留 `(regulation)` / `(news)` 子类型
- **理由**：Yu et al. (2026) 的 OTHER 吸收低频 Move；规章/动态出现率 < 20%，合并入 OTHER 不影响 RQ1–RQ5 核心分析，且保留子类型注记便于后续升级为独立 Move。

## 四、与用户聚类的对应关系总结

- **簇 A**（历史/声誉/缅怀）→ M02 + M08（拆分：历史与缅怀 vs. 声誉与成就）
- **簇 B**（使命/目标/服务/愿景/公共议题）→ M03 + M05 + M10（拆分：价值/目标/愿景）
- **簇 C**（学科/研究）→ M03 + M06（保留两 Move）
- **簇 D**（课程/学习/研究/资源）→ M04 + M06 + M07（拆分）
- **簇 E**（欢迎/行动/募捐/致谢）→ M10 + OTHER（募捐并入 OTHER）
- **簇 F**（联系/规章/动态）→ M10 + OTHER（规章/动态并入 OTHER）

## 五、有据理由汇总

1. **Yu (2023) 的 communicative purpose 准则**：Move 命名应基于 explicit dominant communicative purpose，主语/时间取向不同的 Move 不应合并（簇 B 的目标 vs. 愿景、簇 C 的学科 vs. 研究）。
2. **Yu (2023) 的 10-Move 先例**：10 个 Move 与体裁复杂度匹配，本方案对齐。
3. **Yu et al. (2026) 的 OTHER 吸收策略**：低频 Move（规章/动态/募捐/缅怀）并入 OTHER，保留子类型注记，降低主 Move 数同时保持可追溯性。
4. **RQ 覆盖度**：合并后每个 Move 至少支撑一个 RQ（见 consolidation_rationale_24to10.md §二.理由2）。
5. **标注可靠性**：减少类别数可提升 Cohen's κ（目标 ≥ 0.80）与 corrected accuracy（Yu et al., 2026）。
